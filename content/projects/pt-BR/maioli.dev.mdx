# maioli.dev

O **maioli.dev** nasceu da vontade de criar algo além de um portfólio tradicional.

Eu precisava de um espaço para apresentar meus projetos e minha trajetória profissional, mas não queria que ele fosse apenas uma coleção de cards, tecnologias e links para o GitHub.

Queria que o próprio site também fosse um projeto.

Um lugar onde eu pudesse reunir engenharia, conteúdo e criatividade e, ao mesmo tempo, experimentar ideias que dificilmente fariam sentido em um site corporativo convencional.

## Um portfólio com personalidade

Portfólios de desenvolvedores normalmente seguem uma estrutura bastante parecida.

Isso não é necessariamente um problema. Quando alguém procura informações profissionais, clareza é mais importante do que surpreender.

Mas acredito que existe espaço para as duas coisas.

Por isso, o maioli.dev procura manter as informações fáceis de encontrar enquanto adiciona uma camada de personalidade à experiência.

Uma das formas que encontrei para fazer isso foi através de temas inspirados no universo dos super-heróis.

O visitante pode mudar completamente a identidade visual do site escolhendo diferentes personagens e universos.

Não é uma funcionalidade necessária.

E justamente por isso eu gosto dela.

Ela existe porque software também pode ter personalidade.

## Um pouco de caos

Depois dos temas surgiu outra pergunta:

**e se alguns personagens pudessem interferir no próprio site?**

Foi daí que nasceu o **Chaos Engine**.

Alguns temas não mudam apenas cores. Eles podem provocar pequenos acontecimentos na interface.

Thanos pode fazer elementos desaparecerem.

Loki pode transformar a página em uma pequena brincadeira visual.

Doctor Doom e Magneto também possuem suas próprias formas de interferir na experiência.

São detalhes deliberadamente desnecessários para a função principal do portfólio, mas importantes para aquilo que eu queria que ele transmitisse.

Nem todo código precisa existir apenas para resolver uma necessidade de negócio.

Às vezes ele pode existir simplesmente para criar uma experiência memorável.

## O conteúdo continua sendo o protagonista

Existe, porém, uma regra importante por trás dessas experiências:

**a brincadeira nunca pode atrapalhar o conteúdo.**

Independentemente do tema escolhido ou do efeito acontecendo na tela, projetos, textos e informações precisam continuar acessíveis e compreensíveis.

Essa preocupação acabou influenciando várias decisões durante o desenvolvimento.

Os efeitos são uma camada sobre o site, não a razão pela qual ele existe.

A personalidade pode mudar.

O conteúdo precisa permanecer.

## A mesma história em três idiomas

Outra decisão importante foi não tratar idiomas adicionais como simples traduções adicionadas posteriormente.

O maioli.dev foi pensado para apresentar seu conteúdo em **português, inglês e espanhol**.

Projetos, páginas institucionais e navegação possuem suas versões correspondentes.

Isso é particularmente importante para um portfólio profissional.

A internet elimina grande parte das fronteiras geográficas de uma carreira em tecnologia. Se o trabalho pode chegar a pessoas de diferentes países, o conteúdo também deve estar preparado para isso.

## Cada projeto tem uma história

O GitHub continua sendo o melhor lugar para quem deseja conhecer o código de cada projeto.

Este site possui outro objetivo.

Aqui quero explicar **por que os projetos existem**.

Que problema estava tentando resolver?

O que aprendi construindo aquela solução?

Que decisões mudaram durante o desenvolvimento?

E por que aquele projeto ainda merece fazer parte do meu portfólio?

Por isso, os projetos são apresentados como pequenas histórias, enquanto seus repositórios permanecem disponíveis para quem quiser explorar a parte técnica.

## O próprio portfólio também é um projeto

Talvez essa seja a característica que melhor define o maioli.dev.

Eu não considero o site apenas o lugar onde meus projetos são apresentados.

**Ele também é um deles.**

Novos projetos podem entrar no portfólio.

Novos textos podem ser escritos.

Os temas podem evoluir.

Novas experiências podem aparecer.

Algumas ideias provavelmente serão descartadas no caminho.

E está tudo bem.

Porque este site não foi criado para ser uma fotografia permanente da minha carreira.

Ele foi criado para evoluir junto com ela.
